# ALIGNMENT — 个人应用商店（AppStore）

> 阶段：Phase 1 Align｜状态：待确认｜最后更新：2026-11-25

## 1. 原始需求（用户原文要点）

- 自己开发了很多应用，想做一个应用商店，用于展示与整理已开发提交的应用。
- 可通过该商店进行「分包推送升级」（已澄清：按应用独立版本线推送）。
- 商店分 Web 版与 Android App 版。
- 商店提供 App 版作品的下载；提供网页版作品的预览效果图或已搭建好的跳转超链接。
- 后续可在商店提交新版本；用户端联网检测到新版本可下载安装更新。
- 后续想法需要补充。

## 2. 项目上下文

- 工作区 `c:\Code\AppStore` 为空目录，无既有代码、无 Git 仓库、无既有架构约束。
- 因此本项目的技术约定由本次对齐直接确定，不受历史代码风格限制。

## 3. 任务边界

### 3.1 本次做（In Scope）

| 编号 | 能力 |
|---|---|
| S1 | 应用档案管理：Android 应用与网页作品两类，含图标、简介、分类、标签、截图、可见性 |
| S2 | 版本发布：上传 APK 自动解析包名/版本号/版本名/图标/SHA256，填写更新日志，发布/下架 |
| S3 | Web 前台：应用墙、搜索与标签筛选、应用详情、APK 下载（签名短链）、网页作品跳转 |
| S4 | 管理后台：单管理员登录、应用增删改、版本上传与回滚、下载量查看 |
| S5 | 更新检查接口：按包名 + 当前版本号返回是否有更新、是否强制、下载地址、更新日志、校验值 |
| S6 | Flutter 商店客户端：应用列表/详情、下载进度、调起安装、全局检查更新、商店自身更新 |
| S7 | 更新能力开放示例：提供一处可直接照抄的客户端更新检查接入示例（对接 S5） |
| S8 | 部署配置：环境变量驱动的基地址、下载签名密钥、存储目录，本机/内网可跑 |

### 3.2 本次不做（Out of Scope）

- 多用户注册、用户收藏、评论评分、付费与内购
- 分批灰度放量与多渠道版本线
- iOS 端、Windows/macOS 桌面端
- 应用内自动静默安装（Android 需系统安装器确认，不做 Root/Device Owner 方案）
- 应用市场级推荐算法、运营位与广告
- 第三方登录、对象存储/CDN 接入（预留配置位，不做实现）

## 4. 关键决策记录

| 编号 | 决策点 | 结论 | 理由 |
|---|---|---|---|
| D1 | Web 技术栈与部署形态 | Next.js 单体 + Prisma + SQLite，APK 存本地磁盘，自托管 | 一套应用同时提供前台、后台、API，部署与维护成本最低 |
| D2 | Android 客户端实现 | Flutter | 用户已有 Flutter 经验可复用；安装器与后台任务用原生插件补齐 |
| D3 | 访问与权限模型 | 公开浏览 + 单管理员后台 | 无需注册体系，满足展示与分发诉求 |
| D4 | 「分包推送升级」语义 | 每个应用独立版本线，按应用逐个推送 | 复杂度最低，符合个人多应用维护的实际节奏 |
| D5 | 更新检测归属 | 商店客户端全局检测 + 对外开放标准更新接口（两者都要） | 商店客户端覆盖未改造的老应用；新应用可按需自行接入 |
| D6 | 网页作品展示方式 | 截图 + 跳转链接（新窗口打开） | 不受目标站 X-Frame-Options/CSP 限制，兼容性最好 |
| D7 | 部署环境 | 先本机/内网试用，基地址与密钥全部环境变量化 | 上线只改 `.env`，不返工代码 |

## 5. 需求理解（对原始需求的工程化解释）

1. 「展示与整理」= 一份带分类与标签的应用目录，后台是唯一录入入口，前台无需登录即可浏览。
2. 「提供 App 版作品的下载」= 每个 Android 应用按其最新已发布版本提供 APK 直链下载，同时保留历史版本可回滚。
3. 「网页版作品的预览效果图或跳转超链接」= 网页作品条目含多张截图与一个外部链接，详情页可预览截图并跳转访问。
4. 「用户端联网检测到新版本可下载安装更新」= 客户端定时/手动请求更新接口，比对本地已安装版本号，若有更高版本则提示更新日志并下载，下载完成后调起系统安装器。强制更新由后台按版本配置。
5. 「后续可联动提交新版本」= 后台支持上传新 APK 即完成发版，前台与客户端无需改动即可感知到新版本。
6. 「商店自身更新」= 商店客户端也作为一个受管应用存在于商店中，可用同一套版本与更新机制自更新。

## 6. 关键假设（已按决策固化，如不成立需回调）

- A1：你的应用均为侧载分发（非上架国内应用商店），因此允许申请 `REQUEST_INSTALL_PACKAGES` 与查询已安装包信息的权限。
- A2：Android 11+ 读取其他应用版本号需要 `QUERY_ALL_PACKAGES` 或 `queries` 声明；商店客户端采用前者并在文档中标注。
- A3：单个 APK 体积不超过 200MB，内网/单机磁盘存储足够。
- A4：仅单管理员，无并发写入压力，SQLite 足够。
- A5：网页作品链接为外部可公网/内网访问的 URL，商店不做代理转发。
- A6：不使用 HTTPS 时客户端需允许明文流量（仅限内网试用期），上线切换 HTTPS 后关闭。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Android 各厂商 ROM 对「未知来源安装」限制不一 | 安装失败 | 客户端引导授权 + 失败原因明确提示，不做绕过 |
| 无代码签名一致性校验 | 装错包/被替换 | 记录签名指纹并在详情展示；下载后校验 SHA256 |
| 明文 HTTP 内网试用 | 中间人篡改 APK | 强制 SHA256 校验 + 上线即切 HTTPS |
| 本地磁盘单点存储 | 文件丢失 | 提供存储目录配置与备份说明，不做对象存储实现 |
| 商店客户端自身更新概率死锁 | 无法修复线上问题 | 保留下载页二维码兜底安装路径 |

## 8. 待确认问题

无阻塞性待确认项。以下为已固化的默认值，若需调整请在批准前提出：
- 服务端本机端口默认 `3000`，存储目录默认 `./storage`。
- 管理员账号通过 `.env` 初始化，密码使用 bcrypt 存储，登录态用 HttpOnly Cookie。
