# AppStore — 个人应用分发中心

自建应用商店，用于展示、整理与分发个人开发的作品，并为已安装应用提供版本更新推送。

## 一、项目规划

| 组成 | 技术选型 | 说明 |
|---|---|---|
| Web 端（前台 + 管理后台 + API） | Next.js（App Router）+ TypeScript + Prisma + SQLite | 单体自托管，APK 存本地磁盘，后续可切 Postgres |
| Android 商店客户端 | Flutter | 浏览、下载、安装、检测更新、商店自身自更新 |
| 更新能力开放 | 标准 HTTP 更新检查接口 + 轻量接入示例 | 供自有其他 App 直接接入 |

范围要点：
- 公开浏览 + 单管理员登录后台
- 应用分两类：Android 应用（APK 下载）、网页作品（截图 + 跳转链接）
- 版本线按应用独立（每个应用各自版本号，不做灰度/渠道）
- 更新检测：商店客户端全局检测为主，同时提供标准接口供单个 App 自行接入
- 部署：先本机 / 内网试用，服务端基地址与下载签名密钥全部走环境变量，上线只改配置

里程碑：
1. M1 数据模型 + 管理员登录 + 应用/版本管理 API
2. M2 Web 前台（应用墙、详情、下载）
3. M3 Flutter 商店客户端（列表、详情、下载安装、更新）
4. M4 更新检查接口与接入示例
5. M5 部署配置与商店自更新

## 二、实现策略

- 规格驱动：先 Align（需求与边界）→ Architect（架构与接口）→ Atomize（任务拆分）→ 核准后编码
- 单一数据源：版本、包名、签名指纹、SHA256 全部由上传的 APK 自动解析，人工只填文案与截图
- 下载安全：签名短链 + 完整性校验（SHA256），避免裸路径被爬
- 客户端最小权限：安装未知来源应用按系统规范引导授权，不申请无关权限

## 五、运行与文档

```bash
npm install
npx prisma migrate deploy
npm run build   # prebuild 会自动执行 prisma generate
npm start
```

> 修改 `prisma/schema.prisma` 后，构建前需重新生成 Prisma 客户端；`npm run build` 已内置该步骤，无需手动执行。开发环境可执行 `npx prisma generate && npm run dev`。

### 运行维护

- **健康检查**：`GET /api/health` 返回数据库与存储目录状态，正常为 200，异常为 503，可接入监控探活
- **接口调试**：浏览器直接打开 JSON 接口会渲染美化视图，程序调用仍返回原始 JSON；追加 `?format=json` 可强制原始响应
- **JSON 视图自请求**：美化视图默认通过 `http://127.0.0.1:${PORT:-3000}` 访问自身接口；反向代理端口不同或使用独立内部地址时设置 `INTERNAL_ORIGIN`
- **统计清理**：`npm run analytics:prune` 默认删除 180 天前的事件，可通过 `ANALYTICS_RETENTION_DAYS` 调整，建议每天凌晨执行一次：

```bash
0 3 * * * cd /path/to/appstore && npm run analytics:prune >> logs/analytics-prune.log 2>&1
```
